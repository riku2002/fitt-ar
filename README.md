# Realtime AR Try-On — Virtual Try-On

公開先: [https://fitt-ar.vercel.app](https://fitt-ar.vercel.app)

カメラの姿勢推定結果を共有し、肩と腰に合わせた実写Tシャツを、手のスワイプで切り替えるWebアプリです。

## できること

- カメラの起動・停止・再起動、権限拒否などの案内
- MediaPipe Pose Landmarker Liteによる1人の姿勢推定（目標30回/秒・GPU優先、利用できなければCPU）
- 肩幅・胴体長・傾きに合わせたTシャツの位置・大きさ・回転
- 実写の透過Tシャツ3着（グレー・ミント・赤）。服と骨格の独立した表示切り替え（骨格は初期OFF）
- 胸の高さで手を横に動かすと、次／前の服へ切り替え。ボタン・サムネイルでも選択可能
- 左右の手首それぞれの履歴・信頼度・移動量を確認し、手を戻す動作や連続切り替えを抑制
- 「動作情報」で推定FPS・処理時間・手首の信頼度を表示
- 映像・服・骨格を同時に左右反転
- 肩・腰を見失ったときの服の非表示と、再検出時の復帰
- 服画像の読み込み失敗からの再試行（カメラ・骨格は継続）
- 画面離脱・停止・両方の表示OFFで推定モデルとループを解放

映像・座標はブラウザ内でのみ処理します。録画・保存・サーバー送信・マイク取得は行いません。モデルとWASMもアプリと同じ配信元から読み込みます。

## セットアップ

Node.js **24.x**、npm、Git、Chrome、内蔵またはUSBカメラを使用します。IDEはIntelliJ IDEAを想定しています。

PRのマージ前にこの機能を取得する場合:

```bash
git clone --branch feature/swipe-wardrobe https://github.com/riku2002/fitt-ar.git
cd fitt-ar
node -v
# v24.x.x であることを確認
npm ci
npm run dev
```

マージ後は `git clone https://github.com/riku2002/fitt-ar.git` で取得できます。Clone済みなら、未コミットの変更を確認したうえで `git fetch origin` → `git switch feature/swipe-wardrobe` → `npm ci` を実行してください。

表示されたURL（通常は **http://localhost:5173/**）をChromeで開き、「カメラを起動」→「許可」を選択します。正面を向き、肩から腰まで映る位置に立ってください。

APIキー・環境変数は不要です。モデルとTシャツ画像は同梱済みです。`npm run dev` / `npm run build` の前処理でモデルのハッシュを検証し、npmパッケージに一致するWASMを自動配置します。

nvmを使用している場合は `nvm install` → `nvm use` でNode.jsを切り替えられます。

## 手のスワイプで試着する

1. カメラを起動し、正面を向いて**両肩・腰・動かす手首**が映る位置に立ちます。
2. 片手を胸の高さに上げ、画面の案内が「手を横へスワイプ」になったら、肩幅くらい横に動かします。左右どちらの手でも使えます。
3. **画面上で右 → 左は次の服、左 → 右は前の服**です。鏡表示をOFFにしても、画面上の方向は同じです。
4. 切り替わったら、**手を短く止めて**から次の操作をします。手を下ろしても構いません。連続した往復動作で何度も切り替わることを防ぐため、切り替え後に約0.6秒の待機があります。

グレー → ミント → 赤 → グレーの順で循環します。反応しにくい場合は「前の服」「次の服」ボタンやサムネイルを使えます。「手のスワイプで切り替え」をOFFにすると、手を動かしても服を変えずに試着できます。スマートフォンの画面を指でなぞる操作ではありません。

判定は既存のPose Landmarkerの手首座標を使用します。新しいモデルは追加していません。スワイプには両肩と片方の手首を使い、腰の検出は必須ではありません（服の描画には引き続き腰が必要です）。初期値は、900ms以内・有効な3点以上・肩幅の0.65倍以上の横移動です。移動速度と方向も確認し、単発の座標ジャンプを除外します。短い検出抜けは320msまで許容します。切り替え後は600msの待機と、約240msの静止または手を下ろす動作で次の操作を受け付けます。調整値は `src/features/gesture/swipeDetector.ts` にあります。

### 反応が悪いときに確認すること

カメラ画面の **「動作情報」** を開きます。

- **姿勢推定FPS**：カメラ映像の滑らかさとは別に、手の座標が何回更新されているかを示します。8FPS未満なら少しゆっくり動かし、別タブや重いアプリを閉じて比較してください。
- **推定処理のms・GPU/CPU**：1回の推定にかかった時間と、利用中の処理方式です。GPUの初期化に失敗した場合は自動的にCPUで動作します。
- **手首の信頼度**：動かす手が50%を継続して下回ると判定できません。明るい場所で手首を服や身体に隠さず、画面に映してください。
- 「両肩を画面に」「手首をカメラに」「胸の高さに」の案内で、どの条件が不足しているか確認できます。

調査と比較測定の記録は [スワイプ改善の検証記録](docs/swipe-reliability.md) を参照してください。

## 推定結果の共有

`VirtualMirror` がカメラ1回につき1つの推定セッションを管理します。`poseSession` はCanvasに依存せず、`PoseFrame`（正規化座標・元の動画解像度・タイムスタンプ）を配信します。

```text
Camera → Pose Landmarker → PoseFrame
                              ├─ GarmentOverlay（服）
                              ├─ PoseOverlay（骨格）
                              └─ SwipeGesture（手首履歴 → 服を選択）
```

毎フレームの座標はReact stateに入れず、`PoseSource.subscribe()` で共有します。服の切り替えや骨格の表示変更ではモデルを再生成しません。服と骨格の両方OFFのときは推定を停止し、服がOFFのときはスワイプも無効です。追跡結果が空になった場合や停止時は描画を消去し、動画フレームが500ms以上進まない場合も古い服を残しません。

服・骨格それぞれのCanvasの元解像度を動画に合わせ、同じ `object-fit: contain` と共通の親要素での反転を使います。共有座標そのものは反転せず、ジェスチャーの判定時に画面方向へ変換します。手動の服選択・鏡表示の変更・長い検出中断では途中のスワイプ履歴を破棄します。一瞬の低信頼度だけでは履歴を捨てません。

## デモ服と変換

画像は布目・しわ・縫い目の残った実写の透過PNG3着です。PurePNGがCC0として配布する素材をそのまま同梱しています。出典・利用条件の記録・アンカー座標は [public/garments/README.md](public/garments/README.md) を参照してください。画像生成サービスは使用していません。

**自分の服を追加するには → [写真からTシャツ素材を作る手順書](docs/garment-guide.md)**。撮影・Photopeaでの背景削除・登録・調整・チームへの引き渡しを説明しています。[位置合わせツール](http://localhost:5173/tools/garment-setup.html) では、画像を4か所クリックするだけで設定を作れます。選択した画像はブラウザ内だけで処理します。

- 服のメタデータは `features/wardrobe/garments.ts` に定義します。
- 左右は**着用者から見た左右**です。正面向き画像では左肩が画像の右側です。
- `garmentTransform.ts` は動画のピクセル座標で肩中心・肩幅・傾き・肩に垂直な胴体長を求め、画像から動画への変換行列を返します。
- `garmentRenderer.ts` がその行列で描画します。幅と丈を別々に拡縮し、服全体を回転させる最小実装です。4つのアンカーを独立して変形させるメッシュではありません。
- 肩・腰の4点が信頼度0.5以上かつ画面内なら表示できます。手首・肘の検出は服表示の必須条件ではありません。
- 肩幅や胴体がほぼつぶれた姿勢、背面向きなどは非表示になります。

## 手動確認

自動テストでは推定・座標変換・描画のライフサイクルに加え、スワイプ方向・誤検出抑制・待機・UIとの接続を検証しています。実カメラと端末性能は次の手順で確認してください。

1. ページを開いただけではカメラが起動しないこと。起動・権限許可後に映像と服が表示されること。
2. 正面を向いた状態で左右移動・前後移動・身体の傾きを変え、服の位置・大きさ・傾きが追従すること。
3. 鏡表示を切り替え、画面幅を変えても動画・服・骨格の位置が一致すること。
4. 骨格表示は初期OFF。ON→OFFにしても服が追従すること。骨格ONで服だけをOFFにしても骨格が動くこと。
5. 肩・腰が見え、手首が画面外の状態でも服が表示されること。
6. 画面から離れると服が消え、戻ると再表示されること。
7. 両方の表示をOFFにすると推定が停止し、カメラだけが動くこと。ONで再開できること。
8. カメラの停止・再起動、準備中の停止で古い服や推定処理が残らないこと。
9. カメラ権限の拒否、未接続、切断でも案内が表示されること。
10. 骨格表示をONにしたうえで、開発者ツールのリクエストブロックで `tshirt-gray.png` を止め、服表示をOFF→ONにするとエラーと再読み込みボタンが出ること。骨格は継続し、ブロック解除後に再読み込みで復帰すること。
11. 左右それぞれの手で胸の高さを横切るように動かし、画面右→左で次、左→右で前に切り替わること。鏡表示ON/OFFの両方で確認します。
12. 連続して手を戻す動作では切り替わらず、少し静止してから動かすと、腰まで手を下ろさなくても次の操作ができること。
13. 手の小さな揺れ・上下移動・身体ごとの移動だけでは切り替わらないこと。スワイプOFF・服OFFでも切り替わらないこと。
14. 3着の名前・カウンター・サムネイル・カメラ上の服が一致し、端から次／前へ進むと循環すること。
15. 「動作情報」で推定FPSと処理時間を確認し、画面を止めると古い計測値が残らないこと。反応のよいとき・悪いときのFPSと手首の信頼度を比較します。

## 現段階の制限

独自の平滑化、袖の変形、腕を服の前に出す処理は未実装です。着ている服の上にPNGを重ねるため、元の服が一部見える場合があります。正面向きのデモを想定しており、衣服のサイズ判定を行うものではありません。

GPUを優先しますが、MediaPipeの呼び出しはメインスレッドで同期実行します。低性能端末では30FPSに届かない場合があります。低照度・手首の遮蔽・速すぎる動き・処理落ちではスワイプを検出できない場合があります。デモ機で操作感と「動作情報」を確認してください。Web Workerへの移動は未実装です。

## トラブルシューティング

- カメラは **localhost または HTTPS** で利用してください。スマートフォンからLAN内の通常HTTPへ接続しても使えません。
- Chromeのサイト設定とOSのカメラ権限を確認してください。macOSではシステム設定 → プライバシーとセキュリティ → カメラ、Windowsでは設定 → プライバシーとセキュリティ → カメラを確認します。
- Zoomなど別のアプリがカメラを使用している場合は終了して再試行してください。
- `EBADENGINE` が出たら `node -v` が24.xか確認してください。
- 姿勢推定が失敗した場合は再試行します。繰り返す場合は `npm ci` → `npm run dev` を実行し、モデルファイルの存在を確認してください。
- 公開時は `npm run build` で作成した `dist/` 全体を配信してください。`models/`・`mediapipe/wasm/`・`garments/` が必要です。

参考: [Google Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)、[MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[Canvas変換行列](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/transform)。

## 構成とGitHub開発

```text
src/features/
  camera/            # カメラ取得・解放と画面操作
  pose/              # 推定・PoseFrame配信・骨格表示
  gesture/           # 手首の履歴・スワイプ判定・操作案内
  virtualTryOn/      # 服の変換計算・描画・共通推定セッションの管理
  wardrobe/          # 服のメタデータ・選択UI
public/garments/     # 同梱する透過PNG
public/tools/        # 画像をクリックしてアンカー設定を作る補助ツール
public/models/       # 同梱する推定モデル
scripts/             # WASM配置・モデル検証
docs/garment-guide.md # 自分で素材を撮影・追加する手順書
```

作業ブランチからPRを作成し、`lint` / `typecheck` / `test` / `build` を通してレビュー後にマージします。GitHub Actionsでも同じチェックを行います。
