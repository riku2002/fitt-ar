# 3D服のアンカー設定

この文書は、GLBの肩・腰の基準点を設定し、試着位置を校正する手順です。対象は現在の**3D試着**です。旧2D用のPNGアンカーや `public/tools/garment-setup.html` は、この設定には使いません。

## まず、どちらを直すか決める

| 見え方 | 編集する場所 |
| --- | --- |
| モデルの肩・腰の基準点が、服の実際の肩・腰と合わない | `config/garment-anchors.json` → GLBへ再登録 |
| 基準点は妥当だが、服全体が少しずれる／幅や丈を微調整したい | `src/features/wardrobe/garments.ts` のその服の `fit3D` |
| どの服も同じ方向にずれる、姿勢を変えるとずれが大きく変わる | 姿勢推定・カメラ・追跡条件を先に確認 |

3DレンダラーはGLB内の `AR_LeftShoulder` / `AR_RightShoulder`、または `AR_LeftHip` / `AR_RightHip` を優先します。マーカーがあるモデルでは `fit3D.anchorSpan`、`anchorHeight`、`anchorDepth` を変えてもその基準点は移動しません。`fit3D.offsetX` / `offsetY` / `scaleX` / `scaleY` は、基準点で正規化した後の見た目を調整します。

## 設定値の意味

`config/garment-anchors.json` のキーは `public/garments/` 内のGLBファイル名です。各値はGLBの形状全体を囲む箱に対する割合で、ピクセルや人体の実寸ではありません。登録スクリプトが、この値から名前付きノードをGLBのシーン直下に作ります。

| 値 | 意味 | 調整の目安 |
| --- | --- | --- |
| `axis` | `shoulders` はトップス・ワンピース、`hips` はボトムス | 服の追従基準に合わせる |
| `span` | 左右の肩／腰アンカーの間隔 ÷ モデルの全幅 | 肩点の間隔が狭すぎれば増やす。増やすと試着時のモデル全体は小さくなる |
| `height` | 肩／腰アンカーの高さ。モデルの下端が0、上端が1 | アンカーがモデルの肩／腰より低ければ増やす |
| `depth` | 奥行き方向の基準点。境界箱の手前・奥の間で0～1 | 3Dモデルの基準面を変える場合に調整。画面上の重なりだけなら `fit3D.offsetZ` を先に検討 |
| `centerX` | 左右アンカーの中心。モデルのX最小端が0、X最大端が1。省略時0.5 | 形状や袖が左右非対称なモデルの中心合わせに使う |
| `hipHeight` / `hipSpan` | `axis: shoulders` の服に置く腰アンカーの高さ／間隔 | `fit3D.fitTorsoLength: true` の胴丈補正は左右腰点の**中心**を参照。現行処理では `hipSpan` だけを変えても胴丈は変わらない |

`span`、`height`、`depth`、`hipSpan` は0より大きく1以下です。`hipHeight` は0以上で `height` より小さくします。左右は**着用者から見た左右**で、正面から見た `AR_LeftShoulder` は画面右側です。

## Autumn Girly Topで調整する例

現在の設定は次のとおりです。

```json
"Autumn_girly_top.glb": {
  "axis": "shoulders",
  "span": 0.6,
  "height": 0.84,
  "depth": 0.5,
  "hipHeight": 0.12,
  "hipSpan": 0.48
}
```

1. `npm run dev` で起動し、Autumn Girly Topを選びます。骨格表示をON、手のジェスチャーをOFFにし、鏡表示を固定します。正面を向き、肩と腰が入る距離でスクリーンショットを撮ります。開発画面の「テスト動画を使用」でも同じ姿勢を繰り返して比較できます。
2. モデル上の肩の位置に対し、左右アンカーが内側すぎるなら `span` を、縦位置が低すぎるなら `height` を少し変えます。例えば `span: 0.6` → `0.62`、`height: 0.84` → `0.86` のように**一度に一項目だけ**変えます。これは調整幅の例で、推奨完成値ではありません。
3. 保存後、リポジトリのルートで `node scripts/register-garment-anchors.mjs` を実行します。JSONだけを編集しても、アプリが読むGLB内のアンカーは変わりません。ブラウザを再読み込みし、同じ姿勢で肩・腰・裾を見比べます。
4. アンカーが妥当になった後、服全体の小さなずれは `garments.ts` の `fit3D` で調整します。`offsetX` のプラスは着用者の左、`offsetY` のプラスは上、`offsetZ` のプラスは前です。オフセットの単位は肩アンカー間の幅です。幅・丈は `scaleX` / `scaleY` を1から少しずつ動かします。
5. `npm test` と `npm run build` を実行し、実カメラでも正面・斜め・前後移動を確認します。テスト動画だけでは体格差によるずれは判定できません。

登録スクリプトは設定ファイルに列挙された**全GLB**を処理します。実行後に `git diff --stat -- public/garments` で変更対象を確認し、今回調整する服以外に意図しない差分がないことを確かめてください。既存ノードは更新され、同名ノードは重複しません。形状とテクスチャのバイナリ部分は保持されます。

Autumn Girly Topでは現在 `fit3D.fitTorsoLength` が有効ではありません。そのため `hipHeight` / `hipSpan` を変えても、この服の胴丈は変わりません。肩の位置だけ合って裾が長すぎる／短すぎる場合は、まず `fit3D.scaleY` を調整します。

## 登録経緯と技術メモ

2026-09-30、指定Driveフォルダー内のGLB全10点と「glb追加方法」を確認。10点は同名でもSHA-256と形状・テクスチャが異なる別商品だったため、すべて登録した。トップス5点、ボトムス5点を `men` とし、トップスの試着を優先して検証した。

取得元のDrive ID、元ファイル名、サイズ、取得時SHA-256は `config/garment-sources.json`。同名衝突を避けるためローカル名に連番を付けた。色・形状に基づく商品名はデモ用で、メーカーの商品名ではない。アイコンは取得した実モデルを正面から描画して生成した。

## アンカー

新規10点と既存8点の計18 GLBに、以下の名前付きノードを追加した。

- トップス・ワンピース11点: `AR_LeftShoulder`、`AR_RightShoulder`、`AR_LeftHip`、`AR_RightHip`
- ボトムス7点: `AR_LeftHip`、`AR_RightHip`

左右は着用者基準（正面から見てLeftは画面右）。各GLBのシーン直下に配置するため、モデル内部のピボット・スケール変換に依存しない。既存レンダラーはこれらのマーカーを汎用境界ボックス設定より優先する。

`config/garment-anchors.json` にモデルごとの校正値を保存する。`span` は全幅に対する左右点間隔、`height` は全高での高さ（下端0、上端1）、`depth` は奥行き位置、`centerX` は左右中心（省略時0.5）。上物の `hipHeight` / `hipSpan` は腰の基準。袖の非対称性があるジャケットとスウェットでは左右中心も調整した。

```sh
node scripts/inspect-garments.mjs
node scripts/register-garment-anchors.mjs
npm test
```

登録スクリプトは既存マーカーを更新し、重複を作らない。GLBのJSONチャンクだけを書き換え、バイナリの形状・テクスチャは保持する。既存8点でバイナリ部分が変更前と一致すること、18点で再実行結果がバイト単位で同一になることを検証した。

肩・腰位置はモデルの断面寸法と描画による初期校正で、実人体から採寸した点ではない。既存服は前回の校正位置を引き継ぐ。男性トップスは肩幅に加えて胴丈補正を有効化。ショートパンツは脚長の45%を丈の目安とし、長ズボンは100%とした。既存の伸縮上限は維持している。

## 検証と制限

- 全18モデルの実テクスチャ描画、新規10点・既存8点すべての同梱動画上の試着・切り替えを確認。
- 商品別の実GLB検査を18ケース追加。名前の一意性、シーンへの所属、有限座標、左右の順、肩が腰より上であること、アイコンの存在を検査。
- 196テスト、lint、型チェック、production buildを実行。
- 複数体格の実カメラ試験は未実施。腰回りの寸法・着心地や袖の関節変形は保証しない。モデルごとの袖姿勢は固定のまま。ボトムスは伸縮上限により体格によって丈が不足する可能性があり、デモ優先対象は引き続きトップス・ワンピース。
- 追加GLBは1点あたり約17〜20 MB。今回のローカル読み込み結果は本番回線のロード時間を保証しない。
