# 服切り替えの軽量化（2026-09-30）

## 対応

初回選択ではGLBの取得・デコード・GPUへのアップロードが必要になる。男性服が1点17〜20 MBあり、再選択でも `Box3.setFromObject(..., true)` が全頂点を2回走査していた。

- 全18 GLBを `EXT_meshopt_compression` で圧縮。既存の `useGLTF` はMeshoptデコーダーを同梱しているため、外部デコーダーの追加ダウンロードは不要。
- 頂点位置・UVを16 bit、法線を12 bitに量子化。三角形は削減せず、全テクスチャの画像バイト列とアンカーのワールド座標を維持した。不可逆の精度削減を含むため、元データはDrive／Git履歴に保持する。
- 静的なロード済みモデルの正確な境界を、元シーンと校正設定ごとにキャッシュ。再選択では頂点走査を省く。シーンごと最大8件、WeakMapによりシーンの寿命を延ばさない。スキニング・モーフにはキャッシュを使わない。
- 全商品の先読みは追加していない。初回表示の負荷やメモリ消費を増やさず、必要になったモデルを読み込む。

## 結果

ファイル単位の詳細は `garment-compression.json`（バイト単位）。下表は十進MB。

| 対象 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 全18点合計 | 298.84 MB | 116.29 MB |
| メンズ長袖・ネイビー | 17.45 MB | 6.02 MB |
| メンズジャケット・グレー | 19.08 MB | 7.86 MB |
| ワンピース | 15.69 MB | 4.95 MB |
| スカート | 57.47 MB | 18.14 MB |

合計約61.1%削減。これは容量の削減率であり、切り替え時間の改善率ではない。

Node 24上で同じモデルの境界計算を計測した参考値（最初の1回と、その後100回の平均）:

| モデル | 初回走査 | キャッシュ参照 |
| --- | ---: | ---: |
| メンズ長袖・ネイビー | 9.13 ms | 0.0014 ms |
| ワンピース | 5.66 ms | 0.0007 ms |
| スカート | 16.27 ms | 0.0014 ms |

境界計算のみの計測で、UI操作・通信・デコード・GPU処理を含まない。実機や本番回線での操作から表示までの時間は未計測。

## 検証

- 217テスト、lint、typecheck、production build成功。
- 18点すべてをThreeのローダーで復号するテストを追加。キャッシュの再利用、設定別・モデル別の分離、可変形状の再計算も検証。
- 圧縮前後で全モデルの三角形数・テクスチャのSHA-256が一致。全58アンカーのワールド座標を比較。
- 全モデルの境界差は元モデルの対角長に対して最大約0.00066%。
- 実ブラウザーと同梱動画で全18点の読み込み・試着切り替えとトップスの再選択を確認。
- 描画する三角形数やテクスチャ解像度は維持しているため、低性能端末の常時描画負荷やGPUメモリ使用量は別の検証が必要。

## 更新手順

Node 24で依存関係を導入したうえで、新しい元GLBのアンカーを登録し、最後に圧縮する。

```sh
node scripts/register-garment-anchors.mjs
node scripts/compress-garments.mjs
npm test
npm run build
```

圧縮済みファイルは再量子化せずスキップする。圧縮処理は保存前にアンカー座標・三角形数・画像ハッシュを確認する。`inspect-garments.mjs` もMeshoptの復号に対応済み。
